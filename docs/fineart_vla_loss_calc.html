−100 不是类别，是“这一位不算”

text_labels 和 FAST 目标里的 −100 是 PyTorch cross_entropy(..., ignore_index=-100) 的忽略下标。它不在词表里，不会被当成一个要预测的 token。标成 −100 的位置：分子不加，分母也不计。

注释里的“全 −100，数值为 0”就是这个规则的结果。低层样本的语言段没有 Assistant 目标，分词器把整段 text_labels 都写成 −100。CE 仍然被调用，调用之后分子是 0。

代码只做三步（_lin_ce_small）：

logits   = (hidden @ W.T).float()                         # (N, V)
n_valid  = (labels != -100).sum().clamp(min=1)            # 有效位数，至少为 1
loss     = cross_entropy(logits, labels,
                         ignore_index=-100, reduction="sum") / n_valid

reduction="sum" 先把有效位的负对数似然加起来，再除以有效位数。全是 −100 时，PyTorch 的和是 0；clamp(min=1) 防止除以 0。所以损失是 0 / 1 = 0，梯度也是 0。z-loss 同样乘上 (labels != -100)，全忽略时也是 0。

softmax([2, 0, 0]) 在类别 0 上是 e² / (e² + 1 + 1) ≈ 0.7870，负对数 ≈ 0.2395。类别 1 的那一行对称，同样是 0.2395。

n_valid = 2
CE_sum = 0.2395 + 0.2395 = 0.4790
text_loss = 0.4790 / 2 = 0.2395

z-loss 只加在这两个有效位上。默认权重 10⁻⁴：

lse_t = log Σ_v exp(logits_{t,v})
z = 10⁻⁴ · (lse₂² + lse₃²) / 2
text_loss ← text_loss + z

对 [2, 0, 0]，lse = log(e² + 2) ≈ 2.2395，平方 ≈ 5.0156。两项相同，z ≈ 10⁻⁴ × 5.0156 = 5.02×10⁻⁴。它压低 logits 的整体尺度，不改变“哪一类最大”。

高层样本 predict_actions = False。若这一批全是高层，forward 不跑动作后缀，flow 与 FAST 直接是 0。若和低层混在同一批，flow / FAST 用样本掩码把高层排除出平均。

Flow：只在真实动作维上做 MSE

低层样本才走这条。约定是 FlowConvention.NOISE_AT_ONE。

t ~ Uniform(0.001, 1)
ε ~ N(0, I)　　形状 (1, 50, 32)
x_t = t·ε + (1−t)·a
u_t = ε − a
v_t = action_out_proj(suffix_out[:, −50:])　　float32

a 是归一化后的动作，右侧补零到 max_action_dim = 32。损失先按元素 MSE，再切回原始维度 d（双臂 zip-tie 一般是 12 或 14），再对时间和维度求平均：

mse = (v_t − u_t)²　　无归约，形状 (1, 50, 32)
flow_i = mean( mse_i[:, :, :d] )
flow = Σ_i flow_i · 1[predict_actions_i] / max(1, Σ 1[predict_actions])

默认 flow_num_repeats = 5：前缀只编码一次，后面接 5 组独立的 (ε, t)，注意力是分块对角，5 个 flow 再平均。文本和 FAST 只用第 0 块的前缀隐状态，不重复 5 次。

一个时间步、两个真实维

设 t = 0.25，a = [0.4, −0.2]，ε = [0.0, 0.8]，网络给出 v = [0.1, 0.5]。

x = 0.25·ε + 0.75·a = [0.30, 0.05]
u = ε − a = [−0.4, 1.0]
平方误差 = (0.1−(−0.4))² + (0.5−1.0)² = 0.25 + 0.25 = 0.50
flow = 0.50 / 2 = 0.25

补齐的第 3…32 维不进这个平均。推理时从 t=1 的纯噪声出发，10 步欧拉，每步 Δt = −0.1，x ← x + Δt·v，走到 t=0 得到动作。

FAST：代码位做 CE，其余位改成 −100

第 77 行的“掩码外写成 −100”发生在 _fast_lin_ce，不是分词器。分词器给出 action.tokens 和 action.code_token_mask。损失里先移位，再：

shift_valid   = action_code_mask[:, 1:]          # 下一位确实是 FAST 码
shift_targets = where(shift_valid, action.tokens[:, 1:], -100)

前缀里的 subtask、State、以及 FAST 序列里的填充位，目标都变成 −100，和文本 CE 用同一个 ignore_index。有效位按真实码的个数分组，每组

fast_loss = cross_entropy(logits, targets, ignore_index=-100, reduction="sum") / n_valid

FAST 不加 z-loss。这一批若没有任何 predict_actions 的样本，函数返回 hidden.sum() * 0：数值 0，但仍在图上。
