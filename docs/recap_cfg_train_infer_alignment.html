优势条件 CFG-RL 的训练–推理对齐分析
RLinf 与 LeRobot 对比及落地改造方案

范围：RECAP 打标 → ACP/CFG 策略训练 → HIL / 在线推理
摘要

优势条件策略（ACP）配合无分类器引导（CFG）时，训练阶段对语言提示做路由， 推理阶段用无条件速度场与带 Advantage: positive 的条件速度场做线性混合。 对比 RLinf 官方栈与当前 LeRobot 实现后发现： 打标与训练路由基本对齐； 推理差距最大——RLinf 执行双前缀 CFG 混合，LeRobot HIL 仅单路注入（或关闭）positive 标签， use_cfg / cfg_beta 目前只有配置校验、没有真正生效。 本文给出中文说明、正确渲染公式，以及可落地的文件位置与改造代码草稿。

1. 背景与符号

1.1 正样本打标（positive_ratio = 0.3）

对连续优势 $A_t$，在分组内取分位数阈值（LeRobot 按 task_index；RLinf 多用全局混合）：

$$\tau = Q_{1-\rho}(A),\qquad \mathbb{I}_t=\mathbf{1}[A_t \ge \tau],\qquad \rho=0.3.$$

含义：大约 优势最高的 30% 帧标为 positive，不是随机抽 30%。 这是在构造“更好行为 vs 普通行为”的对比，而不是要求数据集 50/50。

1.2 训练时语言路由（positive_only）

设无条件 dropout 概率为 $p_u$（RLinf: unconditional_prob；LeRobot: indicator_dropout_prob，常用 0.1）：

标签概率 $1-p_u$概率 $p_u$
$\mathbb{I}=1$ task + "\nAdvantage: positive" 纯 task（无条件）
$\mathbb{I}=0$ 始终纯 task（不挂 negative）

训练只对当前路由到的那一条语言做 flow-matching 损失，不做 CFG 线性混合。

1.3 推理时 CFG（RLinf 规范）

$$v=(1-\beta)\,v_{\mathrm{uncond}}(x_t\mid \mathrm{task})+\beta\,v_{\mathrm{cond}}(x_t\mid \mathrm{task},\ \texttt{Advantage: positive}).$$

其中 $\beta=$ cfgrl_guidance_scale（LeRobot 计划用 cfg_beta）。 $\beta=1$ 等价于纯条件；$\beta=0$ 或 no_guide 等价于纯无条件。

2. RLinf vs LeRobot 对比

环节RLinfLeRobot（现状）是否对齐

3. 训练–推理差异分析

高优先级 G1：LeRobot 推理缺少双前缀 CFG 速度混合

RLinf 在每个去噪步同时算 $v_u$ 与 $v_c$ 再混合。 LeRobot 的 PI05Policy.sample_actions 只有一套 tokens/masks 与一套 KV cache， HIL 即使写了 Advantage: positive，也只是硬条件（相当于 $\beta=1$ 的单路），无法调引导强度。

中优先级 G2：部署默认与训练契约不一致

训练开了 ACP；run_hil_collect_data.sh 默认 acp_inference.enable=false。 结果是“训练见过标签，上线却从不给标签”，与 RLinf 默认 positive guidance 相反。

中优先级 G3：Subtask 训练 dropout vs 推理固定 CLI

训练以概率丢掉 Subtask:；HIL 用固定 --subtask 或空。 只要模式明确并打日志即可，但当前缺少统一的 inference mode 枚举。

低优先级：不必担心 ρ=0.3“正样本太少导致映射学坏”

top-30% 是对比构造。帧级数据量通常足够。 推理挂 positive 是在把生成推向高优势条件分布；真正危险的是绝对帧数极少或部署提示与训练完全脱节。 

训练（两边，positive_only）
  I=1 ──(1-p_u)──► lang = task ⊕ Advantage:positive ──► 单路损失
      └─(p_u)────► lang = task
  I=0 ───────────► lang = task

推理 RLinf
  v_u ← denoise(· | task)
  v_c ← denoise(· | task ⊕ Advantage:positive)
  v   ← (1-β) v_u + β v_c

推理 LeRobot HIL（现状）
  enable=false → 单路 task
  enable=true  → 单路 task⊕positive
  use_cfg/cfg_beta → 未进入采样循环

4. 具体改进位置与代码

按依赖顺序改造：先策略采样内核，再 HIL/脚本接线，最后评估对齐。

P1（阻塞）在 Pi05 采样中实现 CFG 双前缀混合

改哪里： src/lerobot/policies/pi05/modeling_pi05.py → 方法 sample_actions（约 L847 起）及调用它的 select_action / predict_action_chunk 路径。
对照实现： /home/xlk/work/RLinf/rlinf/models/embodiment/openpi_cfg/openpi_cfg_action_model.py → sample_actions（约 L693–816）。

为什么：CFG 必须发生在同一噪声轨迹的每一步去噪上。 只改语言字符串、跑一次 forward，得不到 $(1-\beta)v_u+\beta v_c$。

现状（LeRobot，单路）

# modeling_pi05.py :: sample_actions（简化）
prefix_embs, prefix_pad_masks, ... = self.embed_prefix(images, img_masks, tokens, masks)
_, past_key_values = self.paligemma_with_expert.forward(... inputs_embeds=[prefix_embs, None], use_cache=True)

for step in range(num_steps):
    v_t = self.denoise_step(prefix_pad_masks, past_key_values, x_t, timestep)
    x_t = x_t + dt * v_t

目标（对齐 RLinf）

# 伪代码：在 sample_actions 增加可选 cond tokens
def sample_actions(self, images, img_masks, tokens, masks,
                   cond_tokens=None, cond_masks=None,
                   cfg_beta: float | None = None, **kwargs):
    # 1) 无条件前缀 KV
    ..., past_kv_u = embed_and_cache(tokens, masks)

    use_cfg = cond_tokens is not None and cfg_beta is not None and cfg_beta != 1.0
    # 注：beta==1 时可只跑条件路以省算力；beta==0 只跑无条件路
    if cond_tokens is not None:
        ..., past_kv_c = embed_and_cache(cond_tokens, cond_masks)

    for step in range(num_steps):
        v_u = self.denoise_step(prefix_pad_masks_u, past_kv_u, x_t, timestep)
        if cond_tokens is None:
            v_t = v_u
        elif cfg_beta is None or abs(cfg_beta - 1.0) < 1e-6:
            v_t = self.denoise_step(prefix_pad_masks_c, past_kv_c, x_t, timestep)
        else:
            v_c = self.denoise_step(prefix_pad_masks_c, past_kv_c, x_t, timestep)
            v_t = (1.0 - cfg_beta) * v_u + cfg_beta * v_c
        x_t = x_t + dt * v_t
    return x_t

RLinf 对应关键代码（语义一致）： 

v_t_uncond = self.denoise_step(..., past_key_values_uncond, x_t, ...)
v_t_cond   = self.denoise_step(..., past_key_values_cond,   x_t, ...)
v_t = (1 - self.config.cfgrl_guidance_scale) * v_t_uncond \
    + self.config.cfgrl_guidance_scale * v_t_cond

P2 扩展 ACP 推理配置：用 mode 取代含糊的 enable/use_cfg

改哪里： examples/rac/hil_data_collection.py → ACPInferenceConfig（约 L169–172）与 _build_policy_task（约 L175–182）。

为什么：现在 enable 只决定是否拼 positive； use_cfg 有校验但下游没用。应改成与 RLinf guidance_type 一一对应的枚举，避免 silent mismatch。

建议配置

@dataclass
class ACPInferenceConfig:
    # no_guide | cond_positive | cfg_positive
    mode: str = "no_guide"
    cfg_beta: float = 1.0   # 仅 mode=cfg_positive 时使用

    def __post_init_check__(self):
        if self.mode not in {"no_guide", "cond_positive", "cfg_positive"}:
            raise ValueError(...)
        if self.cfg_beta < 0:
            raise ValueError("`cfg_beta` must be >= 0")

建议任务构造

def _build_policy_tasks(cfg: HILConfig) -> tuple[str, str | None]:
    """返回 (uncond_task, cond_task_or_None)。"""
    base = cfg.dataset.single_task
    if cfg.subtask and str(cfg.subtask).strip():
        base = compose_task_with_subtask(base, str(cfg.subtask).strip())

    mode = cfg.acp_inference.mode
    if mode == "no_guide":
        return base, None
    cond = build_acp_tagged_task(base, is_positive=True)
    if mode == "cond_positive":
        # 单路硬条件：只跑 cond（等价 β=1）
        return cond, None
    # cfg_positive：双路
    return base, cond

P3 接线：HIL RTC / sync 与 predict_action

改哪里：
1) examples/rac/hil_data_collection.py → _rtc_inference_thread 里组 obs_batch["task"] 处（现约调用 _build_policy_task）； sync 路径 predict_action(..., task=...)。
2) src/lerobot/utils/control_utils.py → predict_action（约 L68–116）：目前只收一个 task。
3) preprocessor / tokenizer：需要能对同一图像状态产出两套 tokens/masks （可跑两次 preprocessor，或在 processor 支持 task + task_cond）。

为什么：HIL 是部署入口；只改 modeling 不接线，线上仍走单字符串。 RTC 线程与 sync 都必须传齐 uncond/cond。

sync 路径改造示意

# control_utils.predict_action 增加可选参数
def predict_action(..., task=None, task_cond=None, cfg_beta=None, ...):
    obs_u = prepare_observation_for_inference(observation, device, task, robot_type)
    obs_u = preprocessor(obs_u)

    if task_cond is None:
        action = policy.select_action(obs_u)
    else:
        obs_c = prepare_observation_for_inference(observation, device, task_cond, robot_type)
        obs_c = preprocessor(obs_c)
        # 需要 policy.select_action / sample_actions 支持双 tokens + cfg_beta
        action = policy.select_action_cfg(obs_u, obs_c, cfg_beta=cfg_beta)

    return postprocessor(action)

RTC 路径改造示意

# _rtc_inference_thread 内

    obs_batch["task_cond"] = [cond]

改哪里： scripts/run_hil_collect_data.sh（现 --acp_inference.enable=false）； 以及 scripts/run_finetune_recap.sh 旁加一段“部署必须一致”的注释/导出变量。
