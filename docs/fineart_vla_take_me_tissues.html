FineART-VLA：以 take_me_tissues_v30 第一集为例的训练与推理解剖

对照 LeRobot 当前实现。运行例子取 episode 0 的全局 index 0–5。读完后应能独立写出一次 batch size = 1 的前向、损失和推理循环。

代码锚点：datasets/language_render.py，policies/fineart_vla/{configuration,processor,modeling}_fineart_vla.py，policies/pi05/modeling_pi05.py

1. 这篇文档怎么用

全文只跟踪一条真实轨迹。数据集是 /data/huggingface/lerobot/lerobot/take_me_tissues_v30，v3.0，30 Hz，机器人 agilex_cobot，29 集、56033 帧。第 0 集占全局 index [0, 2388)，时长 79.6 s。任务句来自 meta/tasks.parquet：

Please take a pack of tissues from the drawer next to you, then pull out one sheet and give it to me.

观测是三路 480×640 视频 high / left / right，状态和动作都是 16 维：左臂 7 关节、右臂 7 关节、vx、vtheta。语言已经写进每一帧的 language_persistent；language_events 在这一集是空列表。默认配方只用 ${task} 和 ${subtask}，同集里的 memory 行不进入损失。

3. 默认配方，以及 BLAKE2b 如何抽成高层或低层

3.1 _fineart_vla_default_recipe

函数在 src/lerobot/policies/fineart_vla/configuration_fineart_vla.py。它返回一个字典，FineARTVLAConfig.recipe 用它当默认值。训练时 TrainingRecipe.from_dict 再把它收成对象。${task} 和 ${subtask} 是占位符，真正的字符串要等 render_sample 去填。

def _fineart_vla_default_recipe() -> dict:
    """不 import 数据集模块，只把子任务契约嵌进配置。"""
    return {
        "blend": {
            # 约 30% 的样本：任务句 → 子任务，只做文本交叉熵
            "high_level_subtask": {
                "weight": 0.30,
                "messages": [
                    {"role": "user", "content": "${task}", "stream": "high_level"},
                    {
                        "role": "assistant",
                        "content": "${subtask}",   # 由 active_at(t, style=subtask) 填入
                        "stream": "high_level",
                        "target": True,            # 这一轮的 token 写入 text_labels
                        "if_present": "subtask",   # 当前时刻没有子任务就整轮丢掉
                    },
                ],
            },
            # 约 70% 的样本：子任务 → 动作。没有 assistant target，所以没有文本监督
            "low_level_execution": {
                "weight": 0.70,
                "messages": [
                    {
                        "role": "user",
                        "content": "${subtask}",
                        "stream": "low_level",     # 流名让 tokenizer 打开 predict_actions，并拼接 State:
                        "if_present": "subtask",
                    }
                ],
            },
        }
    }

3.2 BLAKE2b 抽签，按字节展开

RenderTrainingMessagesStep 把数据集列 index 当作 sample_idx。抽签在 _select_recipe（同样是 language_render.py）。它不用随机数，同一 index 每次训练都走同一条路线。

def _select_recipe(recipe, sample_idx):
    components = [c for c in recipe.blend.values() if c.route is None]
    # 默认配方：先 high_level_subtask(0.30)，再 low_level_execution(0.70)
    total_weight = sum(c.weight or 0.0 for c in components)   # = 1.0

    # 1) 把 index 的十进制字符串编码成字节。index 0 → b"0"，index 2 → b"2"
    digest = hashlib.blake2b(str(sample_idx).encode(), digest_size=8).digest()
    # 2) digest 是 8 字节。按大端读成 0 .. 2^64-1 的整数
    # 3) 除以 2^64 得到 [0, 1) 的小数，再乘总权重
    draw = int.from_bytes(digest, "big") / 2**64 * total_weight

    cumulative = 0.0
    for component in components:          # 字典顺序：先 0.30 的高层，再 0.70 的低层
        cumulative += component.weight or 0.0
        if draw < cumulative:
            return component
    return components[-1]

BLAKE2b 在这里只被当作一个把整数映到 64 比特的函数。digest_size=8 表示只要 8 字节（64 比特），不是默认的 64 字节。展开成三步：

$$\mathrm{digest}=\mathrm{BLAKE2b}_{8}(\text{UTF-8}(\mathrm{str}(i)))\in\{0,1\}^{64}$$ $$n=\sum_{k=0}^{7}\mathrm{digest}[k]\cdot 256^{7-k}$$ $$\mathrm{draw}=n\,/\,2^{64}\times 1.0$$

累计权重先加高层的 0.30。draw < 0.30 返回高层，否则继续加上 0.70，累计到 1.0，返回低层。

4. 数据进入模型之前

4.1 数据集读出一块动作

LeRobotDataset 按策略的 delta_timestamps 取未来动作。默认 chunk_size=50、fps=30，index 0 的动作目标是

$$A_{0}=\{a_{0},a_{1},\ldots,a_{49}\}\in\mathbb{R}^{50\times 16}$$

图像按时间戳从三路 AV1 视频解码出 \(480\times 640\times 3\)。相对动作默认关闭（use_relative_actions=False），所以 \(A\) 是绝对关节位置，减去当前状态这一步不发生。

4.2 分位数归一化

状态和动作走 NormalizationMode.QUANTILES，统计量是 meta/stats.json 的 \(q_{01}, q_{99}\)。图像走 IDENTITY，像素缩放留给视觉塔。

$$\tilde x = 2\cdot\frac{x-q_{01}}{q_{99}-q_{01}}-1$$

这个映射不裁剪。停在起点的关节经常落在数据集分布的尾巴外，\(\tilde x\) 可以小于 \(-1\) 或大于 \(1\)。index 0 的 16 维状态经过数据集分位数之后是：

−0.180, −1.010, 1.000, 0.856, 0.021, −0.068, −1.001, −0.095, −1.000, 1.000, −0.838, −0.943, 1.201, 4.804, −0.183, 0.821

动作块的每一行做同样的变换，再在最后一维补零到 max_action_dim=32，得到模型内部的 \(A\in\mathbb{R}^{1\times 50\times 32}\)。损失只回看前 16 维。

4.3 低层 prompt：index 0

渲染结果只有一轮 user，流是 low_level，没有 target: true。Tokenizer 步发现流里有 low_level，就把分位数后的状态离散成 256 个箱子并接到句尾。discretize_state_str 的箱子边界是 \(\mathrm{linspace}(-1,1,257)[:-1]\)。落在 \([-1,1]\) 外的分量变成 \(-1\) 或 \(255\)。index 0 的正文是：

User: drive forward along the office aisle toward the desk bench, State: 105 -1 255 237 130 119 -1 115 -1 255 20 7 255 255 104 233;

右填充到 200。因为没有 assistant 监督跨度，text_labels 形状 (1, 200)，全部是 \(-100\)。predict_actions 是 True。

4.4 高层 prompt：index 2

抽签落在高层。user 是任务句，assistant 是当时的子任务，assistant 标成监督目标：

User: Please take a pack of tissues from the drawer next to you, then pull out one sheet and give it to me.
Assistant: drive forward along the office aisle toward the desk bench

高层流不是 low_level，所以不拼接 State:。text_labels 只在 assistant 子任务的 token 上等于 input id，user 和 padding 都是 \(-100\)。predict_actions 是 False。图像仍然进 prefix，模型看的是同一时刻的三张图。

4.5 图像 token

每路相机缩到 \(224\times 224\)，像素映射到 SigLIP 期望的 \([-1,1]\)。patch 14 给出 \(16\times 16=256\) 个视觉 token。三路相机拼起来是 768 个图像 token，注意力段标记为 0，也就是图像内部双向可见。语言最多再接 200 个 token。低层若打开 FAST，动作码还接在语言后面，prefix 最长大约 \(768+200+256\)。

4.6 processor_fineart_vla.py：两条样本各自怎么走

这个文件做三件事：把归一化后的状态写成 State: 字符串、把渲染好的对话编成 token 和标签、以及 make_fineart_vla_pre_post_processors 把前面的步骤串成流水线。配方抽签不在这个文件里，它发生在流水线中的 RenderTrainingMessagesStep。下面按 index 0（低层）和 index 2（高层）各走一遍。

_encode_messages 的四步

默认配方没有 VQA JSON，也没有 say 工具调用，所以 _messages_vqa_to_loc 和 _flatten_say_tool_calls 对这两条样本是原样返回。_strip_blocks 只是去掉消息上的 stream / target 字段。

第一步，只有低层才拼接本体。代码是：

def discretize_state_str(state_row):
    arr = state_row.detach().cpu().numpy()
    # 257 个等分点去掉最后一个，得到 256 个左边界，覆盖 [-1, 1)
    disc = np.digitize(arr, bins=np.linspace(-1, 1, 256 + 1)[:-1]) - 1
    return " ".join(str(int(x)) for x in disc)

# _encode_messages 内
if state_row is not None and any(s == "low_level" for s in message_streams):

index 0 的 message_streams 含 low_level，于是 user 正文变成

drive forward along the office aisle toward the desk bench, State: 105 -1 255 237 130 119 -1 115 -1 255 20 7 255 255 104 233;

箱子里的 −1 和 255 来自分位数没有裁剪：小于 −1 的分量 digitize 得到 0，再减 1 变成 −1；大于最后一个边界的分量得到 256，再减 1 变成 255。index 2 的流全是 high_level，这个 if 不进入，正文保持任务句和子任务两行，没有 State:。

第二步，_format_messages 把每轮写成 Role: 正文\n。监督轮的正文末尾会加上 tokenizer 的 EOS，这样模型学得到哪里停。字符区间 (start, end) 只覆盖正文，不覆盖 User: 这种头。

header = f"{role.capitalize()}: "          # "User: " 或 "Assistant: "

index 0 没有 target，拼出来是一行：

User: drive forward along the office aisle toward the desk bench, State: 105 -1 255 ...;

index 2 的 target 下标是 1，assistant 正文带 EOS：

User: Please take a pack of tissues from the drawer next to you, then pull out one sheet and give it to me.
Assistant: drive forward along the office aisle toward the desk bench<eos>

第三步，PaliGemma tokenizer 右填充或截断到 200，并返回每个 token 在原文字符串里的 offset_mapping。标签先全部写成 −100，再把与监督区间重叠、且 attention mask 为真的 token 改回它们自己的 id：

labels = torch.full_like(input_ids, fill_value=-100)
overlaps = (offsets[:, 1] > span_start) & (offsets[:, 0] < span_end)
labels = torch.where(attention_mask & overlaps, input_ids, labels)

index 0 的 target_indices 是空列表，labels 保持 200 个 −100。index 2 只有 “Assistant: ” 后面的子任务 token（含 EOS）等于 input id，user 句和右侧 padding 仍是 −100。

第四步，predict_actions 只看流名，不看有没有动作张量：

predict_actions = torch.tensor(any(s == "low_level" for s in message_streams))
# index 0 → True ；index 2 → False

返回值五个：input_ids (200,)、attention_mask (200,)、labels (200,)、predict_actions 标量、prompt 字符串。__call__ 再 stack 成 batch 维 1，写进 observation 和 complementary。训练循环随后把 text_labels 和 predict_actions 放进 policy.forward 看到的 batch。高层步因此 run_flow=False，低层步 run_flow=True。

FAST 步接在 tokenizer 后面，只在 enable_fast_action_loss=True 时存在。它读的是已经归一化、补到 32 维的动作块，编成动作码。低层 predict_actions=True 时这些码进入前向；高层该标志为 False，模型侧的 run_fast 直接关掉，码即使被编出来也不进损失。

4.7 语言怎么变成 input_ids，−100 标在哪，训练时谁用它们

状态拼接、分词、input_ids 和 text_labels 是四件不同的事。状态先变成字符串，拼进 user 正文；分词器再把整段字符串切成整数；input_ids 是切出来的全部整数，模型用它查词嵌入；text_labels 是一条平行的长 200 的整数，只有要预测的位置抄 input_ids，其余位置写成 −100。−100 不是词表里的 token，PaliGemma 的 pad 是 0、bos 是 2、eos 是 1。

从句子到字符串

分词器看不到 ${subtask}，也看不到 16 维浮点状态。它只看到 _format_messages 拼好的一串字符。本地 pretrain_model/paligemma-3b-pt-224 的特殊符号是 <bos>=2、<eos>=1、<pad>=0，add_bos_token=true，所以每条样本开头都会被自动加上 id 2。

index 0（低层）在分词前的完整字符串是下面这一行，末尾有一个换行。状态不是额外的张量，而是这句话里面的数字：

User: drive forward along the office aisle toward the desk bench, State: 105 -1 255 237 130 119 -1 115 -1 255 20 7 255 255 104 233;

index 2（高层）有两轮。只有 assistant 是 target，所以只在子任务正文后面插入字符串 <eos>，user 轮不加：

User: Please take a pack of tissues from the drawer next to you, then pull out one sheet and give it to me.
Assistant: drive forward along the office aisle toward the desk bench<eos>

_format_messages 同时记下 assistant 正文在这串字符里的半开区间。这条样本的区间是字符 [119, 182)，也就是从 drive 的前导空格到 <eos> 结束，不含 Assistant: 这几个字，也不含最后那个换行。

分词器做了什么

FineARTVLATextTokenizerStep._encode_messages 调用的是 PaliGemma 的 SentencePiece tokenizer，参数固定为 max_length=200、padding="max_length"、padding_side="right"、truncation=True、return_offsets_mapping=True。返回三样东西：

返回键形状含义
input_ids(200,) 再 stack 成 (1, 200)每个子词的词表编号。右边不够的位置填 pad id 0
attention_mask同样 (1, 200) 的 bool真实 token 为 True，pad 为 False。模型用它丢掉填充位置
offset_mapping每个 token 一对 (char_start, char_end)这个子词对应原字符串的哪一段。用来决定标签，不进模型

−100 怎么写上

标签先整条写成 −100，再按字符区间把该监督的位置改回 input_ids 里的同一个数。代码是：

labels = torch.full_like(input_ids, fill_value=-100)   # 200 个 -100
# 一个 token 被监督，当且仅当：
#   attention_mask 为 True（不是 pad）
#   并且它的 [char_start, char_end) 与某个 target span 有重叠
overlaps = (offset_end > span_start) & (offset_start < span_end)
labels = torch.where(attention_mask & overlaps, input_ids, labels)

index 0 没有 target span，重叠永远不成立，所以 text_labels 是 200 个 −100。input_ids 仍然是上面那 73 个真实 id 加 pad。模型看得到这句话，只是没有任何一个位置要被交叉熵预测。

index 2 切出 42 个有效 token。字符区间 [119, 182) 盖住子任务和 <eos>，盖不住 Assistant:，也盖不住它后面的换行。于是只有位置 30 到 40 的标签等于 input_ids，其余仍是 −100：

这两条张量在训练里各走各的

input_ids 进 embed_prefix，经 embed_language_tokens 变成语言嵌入，和 768 个图像 token 拼成 prefix。每个位置都参与前向，包括 user 句和 pad 以外的全部有效 token。pad 被 attention mask 挡掉。

损失不直接拿 input_ids 当目标。交叉熵在 _shifted_lin_ce 里把序列错开一位，这是标准的“用当前位置的 hidden 预测下一个 token”：

shift_hidden = hidden[:, :-1, :]    # 位置 0 .. 198 的隐藏状态
shift_labels = text_labels[:, 1:]   # 位置 1 .. 199 的标签
loss = cross_entropy(lm_head(shift_hidden), shift_labels, ignore_index=-100)

index 2 上，真正产生损失的配对只有 11 个。位置 29 的 hidden（它读到的最后一个前缀 token 是 :）去预测位置 30 的 drive；位置 39 的 bench 去预测位置 40 的 <eos>。user 句、角色头、换行和 pad 的标签是 −100，ignore_index=-100 把它们从分子里去掉。分母是非 −100 的个数，这里是 11。

index 0 的标签全是 −100。错位之后仍然全是 −100，交叉熵分子是 0。这句话的 input_ids 照样嵌进 prefix，给流匹配当条件；它只是不提供文本梯度。predict_actions=True 才是这一步要训练动作的原因，和标签里的 −100 是两套开关。

5. 模型里有什么

FineART-VLA 是 π0.5 的联合主干，外加配方文本损失。两条流共享层号，权重分开：

部件默认吃什么谁更新它
SigLIP + Gemma 2B（PaliGemma）gemma_2b图像 token、语言 token、FAST 码文本交叉熵、FAST 交叉熵
Gemma 300M action expertgemma_300m50 个带噪动作 token，时间用 AdaRMS 注入流匹配损失
action_in_proj / action_out_proj32 维动作向量与速度流匹配损失
lm_head与词嵌入同形；π0.5 权重里若缺则从 embed_tokens 拷贝语言和 FAST 的 hidden两种交叉熵

一次训练步只实例化一条路线。高层步的 inputs_embeds 是 [prefix, None]，action expert 不参与。低层步是 [prefix, suffix]，两条流在每一层做联合注意力。

默认超参：flow_loss_weight=10，text_loss_weight=1，fast_action_loss_weight=1，enable_fast_action_loss=True，flow_num_repeats=5，knowledge_insulation=True，text_ce_z_loss_weight=10^{-4}，num_inference_steps=10。时间采样是

$$t=\mathrm{Beta}(1.5,\ 1.0)\cdot 0.999+0.001\in(0.001,\ 1]$$

6. 训练：index 2，高层，只有文本损失

FineARTVLAPolicy.forward 看到 predict_actions=False，于是 run_flow=False、run_fast=False、run_text=True，进入 _compute_text_and_fast_loss。

Algorithm 1  高层一步（batch = 1，index = 2）
输入: 三张图 I，语言 token x[1,200]，标签 y[1,200]
1  prefix ← EmbedPrefix(I, x)                         # 约 768 + 200
2  把 y ≠ −100 的位置在注意力段标记里改成因果
   # _mark_target_span_causal：prompt 双向，子任务 token 看不到右侧子任务 token
3  H ← PaliGemma(prefix)                              # inputs_embeds = [prefix, None]
4  取语言段最后 200 个 hidden，右移一位
5  L_text ← CrossEntropy(lm_head(H[:, :-1]), y[:, 1:]; ignore −100)
6  若 z > 0: L_text ← L_text + z · mean(logsumexp(logits)^2) 在有效位置上
7  返回 L = 1 · L_text
   action expert、flow、FAST 本步梯度为 0

有效的预测位置就是 “drive forward …” 这些子任务 token。图像 token 通过注意力把视觉信息送进这些位置，所以视觉塔在高层步里是被文本损失更新的。

7. 训练：index 0，低层，流匹配加 FAST

predict_actions=True，默认 FAST 打开，所以 run_flow 和 run_fast 同时为真，走 _compute_all_losses_fused。因为 flow_num_repeats=5，实际调用的是 _amortized_prefix_and_flow：同一条 VLM prefix 配 5 组独立的噪声和时间。

流匹配约定是噪声在 \(t=1\)：

$$x_t = t\,\epsilon + (1-t)\,A,\qquad u_t = \epsilon - A,\qquad \epsilon\sim\mathcal{N}(0,I)$$

5 组 suffix 在序列上首尾相接，形状是 (1, 5×50, D)。注意力是分块的：prefix 看不到任何动作块；每个动作块只看 prefix 和自己那 50 个 token，5 组之间互不可见。若 FAST 码接在语言后面，动作块还被禁止看 FAST 段，避免动作码把答案直接漏给速度头。FAST 与流的 RoPE 位置从非 FAST prefix 的末尾重新起算，这样推理时没有 FAST 段，位置编号仍然对齐。

Algorithm 2  低层一步（batch = 1，index = 0，K = 5）
输入: 图 I，低层 prompt x，标签 y 全 −100，动作 A[1,50,32]，FAST 码 c
1  prefix ← EmbedPrefix(I, x)
2  把 FAST 嵌入接到 prefix 末尾；语言对 FAST 不可见（段掩码）
3  对 k = 1..5:
     ε_k ~ N(0,I),  t_k ~ Beta(1.5,1)·0.999+0.001
     x_k = t_k ε_k + (1−t_k) A
     u_k = ε_k − A
4  一次联合前向 (prefix_out, suffix_out) ← JointLayers(prefix, concat_k suffix)
   每一层:
     VLM query 使用未断开的 K/V
     action query 使用 detach(VLM K/V) ⊕ expert K/V     # knowledge_insulation
5  v_k = action_out_proj(suffix_out 的第 k 块)          # [1,50,32] → 取前 16 维
6  L_flow = mean_k mean_{h,d} (v_k − u_k)^2
7  L_text = CE(语言段, y)                               # y 全是 −100，这一项为 0
8  L_fast = CE(FAST 段的动作码位置, c)，同样忽略非码位置
9  返回 L = 10·L_flow + 1·L_text + 1·L_fast

知识隔离在 compute_layer_complete 里，FineART 在构造时把 paligemma_with_expert.knowledge_insulation 设为配置值。动作 query 对 VLM 的 K/V 做 detach，流匹配的梯度因此到不了 VLM。VLM 自己的 query 仍使用未断开的 K/V，所以 FAST 交叉熵可以更新视觉塔和语言模型。文本项在这一步因为标签全是 \(-100\) 而等于 0。

另一条更强的开关是 suppress_prefix_grads：只有 text_labels is None 且没有 FAST token 时，才把整个 prefix 放进 no_grad。默认低层步两者都在，这条开关是关的。隔离靠的是注意力里的 K/V detach，prefix 的 FAST 损失仍然回传。

8. 推理：先生成子任务，再积分动作

推理不走 forward，也不抽配方。控制器先做一次语言生成，再把生成的句子填进低层 prompt，然后去噪。两次调用的 batch 都是 1。generate_text 在 batch 不是 1 时直接报错。

Algorithm 3  在 t = 0 部署一次（batch = 1）
输入: 三张当前图 I，当前状态 s，任务句 task
# ---- 高层 ----
1  prompt ← "User: {task}\nAssistant:"
   # 运行时没有训练标签，tokenizer 会补上 Assistant:，对齐训练里目标段的前缀
2  自回归，最多 128 个新 token，temperature = 0，即 argmax
   每步屏蔽 FAST 专用词表；子任务生成再屏蔽 <loc> id [256000, 257024)
   默认使用 KV cache：第一步算完整 prefix，之后只喂最新 token
3  遇到 EOS 停止，解码得到 ŝ，例如
   "drive forward along the office aisle toward the desk bench"
# ---- 低层 ----
4  把 s 做与训练相同的分位数归一化，离散成 State 串
5  prompt ← "User: {ŝ}, State: {bins};"
6  可选：把 ŝ 对应的 token 标成 lang_causal_marks，
   让推理 prefix 的因果布局与训练时的 _mark_target_span_causal 一致
7  预计算 prefix 的 K/V（只跑 VLM，use_cache=True）
8  x ← ε ~ N(0, I)，形状 (1, 50, 32)
9  对 n = 0 .. 9:                         # num_inference_steps = 10
     t ← 1 − n/10
     v ← action_out_proj(Expert(x, t | cached prefix K/V))
     x ← x + dt · v                      # dt < 0，从噪声走到动作
     每步之后把 suffix 的 K/V 裁掉，prefix cache 保持只读
10 返回 x[:, :, :16]，再按 q01/q99 反映射回关节单位

去噪方向与训练一致：\(t=1\) 是噪声，\(t=0\) 是动作，\(v\) 预测的是 \(\epsilon-A\)，欧拉步 \(x\leftarrow x+dt\,v\) 且 \(dt<0\)。10 步之后得到未来 \(50/30\approx 1.67\) s 的 16 维指令。默认 n_action_steps=50，这一整块都会被执行；若外层只取前几步，剩余步留到下一次推理做实时分块，那是 RTC，默认 rtc_training_max_delay=0，本文的主路径不含它。

推理时的子任务是模型自己写出来的。训练时 index 0 看到的是标注句 “drive forward …”。两者在格式上相同：低层 user 轮、同一套 State: 离散化、同一套 10 步欧拉积分。高层生成不经过 action expert。

10. 把一次训练写成可执行的伪代码

def train_step(sample):  # sample.index ∈ {0,1,2,...}
    imgs, state, actions, t, persistent, task = load(sample)   # actions: (50,16)
    state_n  = quantile(state,  q01_s, q99_s)                  # (16,)
    action_n = quantile(actions, q01_a, q99_a)                 # (50,16)
    A = pad(action_n, 32)                                      # (1,50,32)

    route = "high" if blake2b_unit(sample.index) < 0.30 else "low"
    sub = active_at(t, persistent, style="subtask").content
    # t=0 → "drive forward along the office aisle toward the desk bench"

    if route == "high":                      # index 2, draw=0.109
        text = f"User: {task}\nAssistant: {sub}"
        ids, labels = tokenize_with_target(text, target="Assistant 段")
        H = vlm(embed(imgs, ids))
        loss = ce(lm_head(H), labels)        # + 1e-4 * z_loss
    else:                                    # index 0, draw=0.516
        bins = discretize_256(state_n)       # "105 -1 255 ..."
        text = f"User: {sub}, State: {bins};"
        ids, labels = tokenize(text)         # labels 全 −100
        fast = fast_tokenize(A)              # 默认开启
        prefix = cat(embed(imgs, ids), embed(fast))
        flow = 0
        for k in range(5):
            eps = randn_like(A)
            tk  = beta(1.5, 1.0) * 0.999 + 0.001
            xt  = tk * eps + (1 - tk) * A
            ut  = eps - A
            # 五次循环在实现里是一次前向、块对角注意力
            vt  = action_out_proj(expert(xt, tk | prefix, detach_vlm_kv=True))
            flow += mse(vt[..., :16], ut[..., :16])
        flow /= 5
        loss = 10 * flow + ce(vlm_hidden, labels) + ce(fast_hidden, fast)
    loss.backward()
    clip_grad_(1.0)
    adamw_step()

def infer_step(imgs, state, task):
    sub = generate_text(imgs, f"User: {task}\nAssistant:")   # greedy, B=1
    bins = discretize_256(quantile(state, q01_s, q99_s))
    ids = tokenize(f"User: {sub}, State: {bins};")
    kv = vlm_cache(embed(imgs, ids))
    x = randn(1, 50, 32)
    for n in range(10):
        t = 1 - n / 10
        v = action_out_proj(expert(x, t | kv))
        x = x + (-1/10) * v
    return unquantile(x[..., :16], q01_a, q99_a)

11. 对照时容易写错的几点

事实依据
index 0 是低层步，index 2 才是高层步_select_recipe 的 BLAKE2b，权重 0.30/0.70
同一帧的 memory 不进默认损失默认配方只引用 ${task} 与 ${subtask}
