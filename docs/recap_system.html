当前代码中的 RECAP：
软件架构、算法与落地步骤

实现说明 · 以 scripts/run_finetune_recap.sh 与 examples/rac/hil_data_collection.py 为准
摘要

本系统把离线示教与人在回路数据迭代成优势条件策略。数据流分为四段：分布价值模型、N 步优势与分位数标签、带语言 dropout 的 flow-matching 策略、带可选 CFG 的在线采集。 价值网络为 Pi\*0.6。价值目标有两种互斥模式：remaining_steps（当前脚本默认，与 Evo-RL 的目标及优势一致）和 recap_returns（RLinf 回报）。 策略训练默认只对高优势帧附加 Advantage: positive。推理在 Pi0.5 的去噪速度上做引导；引导系数约为 1 时退化为单路条件采样。 采集不在线写优势标签。标签在离线 value-infer 中写回数据集，供下一轮策略使用。

1. 软件架构

一次迭代由四个进程阶段和一次机器人采集组成。阶段开关在 run_finetune_recap.sh 顶部，当前默认为价值训练、价值推理、统计重算打开，策略训练关闭。

2. 数据契约

价值与标签依赖回合级 episode_success（success 或 failure）。字段缺失时按 default_success=failure 处理。帧级可选 complementary_info.is_intervention。策略语言来自 task；若打开子任务条件，还需要能解析出的 subtask 文本（meta/subtasks.parquet 加帧上的 subtask_index）。

value-infer 写回两列，名字由脚本指定，当前为 advantage_continuous 与 complementary_info.acp_indicator。采集帧里的 task 始终是高层原文，不含 Advantage 标签。

3. 价值模型

Pi\*0.6 用 SigLIP 编码多相机图像，用 Gemma 编码 Task: …, State: …，头部为 $[-1,0]$ 上 201 个 bin 的 logits。预测值是 bin 中心的期望。损失是软标签交叉熵，不是均方误差。本体状态只出现在文本里。

两种目标互斥，训练与推理必须使用同一个 RECAP_TARGET_MODE。

3.1 remaining_steps

$$g_t=-(L-t-1)-\mathbf{1}[\mathrm{fail}]\,L_{\max}\,c_{\mathrm{fail}},\qquad V^\star_t=\mathrm{clip}\!\left(\frac{g_t}{L_{\max}+c_{\mathrm{fail}}},-1,0\right).$$

$L_{\max}$ 是该 task_index 的最长回合。脚本未覆盖 c_fail_coef，因此使用默认值 1。此模式不使用 $\gamma$ 与 failure_reward。

3.2 recap_returns

$$r_t=\begin{cases}-1,& t<T-1,\\ 0,& \text{成功终止},\\ R_{\mathrm{fail}},& \text{失败终止,}\end{cases}\quad G_t=r_t+\gamma G_{t+1},\quad V^\star_t=\dfrac{G_t-G_{\min}}{G_{\max}-G_{\min}}-1.$$

脚本中 $\gamma=1$、$R_{\mathrm{fail}}=-300$。归一化范围是整个数据集的回报，不是单个任务的长度。

4. 优势与二值标签

连续优势由价值预测 $V$ 与第 3 节的奖励共同构成。两种模式的 $r_t$ 不同，因此 $A_t$ 不可互换。

remaining_steps. 令 $r_t=V^\star_t-V^\star_{t+1}$（最后一帧 $r_t=V^\star_t$），

$$A_t=\sum_{k=0}^{N-1} r_{t+k}+V_{t+N}-V_t.$$

走不满 $N$ 步时 bootstrap 为 0。无折扣。

recap_returns.

$$A_t=\mathrm{norm}\!\left(\sum_{k=0}^{N-1}\gamma^k r_{t+k}\right)+\gamma^{N_{\mathrm{valid}}}V_{t+N}-V_t.$$

$\mathrm{norm}$ 使用与 $G$ 相同的全局映射，使奖励和与 $V$ 同尺度。discount_next_value=false 时 bootstrap 上的折扣指数改为 1。

二值化与模式无关：对每个 task_index，

$$\tau=Q_{1-\rho}(A),\qquad \mathbb{I}=\mathbf{1}[A\ge\tau],\qquad \rho=0.3.$$

FORCE_INTERVENTION_POSITIVE=true 时，干预标志大于 0.5 的帧强制为 1。当前脚本 $N=32$。若 RECAP_USE_EXISTING_ADVANTAGE=true，则跳过价值模型，只对已有连续列做上述分位数，不再按 target_mode 重算 $A_t$。

5. CFG-RL 策略训练

每个 batch 在 preprocessor 之前改写 task。若 CONDITION_ON_SUBTASK=true，先按概率丢掉 Subtask:，再做 ACP。当前脚本关闭子任务。ACP 由 POSITIVE_ONLY_CONDITIONAL=true 与 INDICATOR_DROPOUT_PROB=0.1 控制：

indicator概率 $1-p$概率 $p=0.1$
1任务文本加 Advantage: positive纯任务文本
0始终纯任务文本，不写 negative

Pi0.5 在单路提示上做 flow-matching。训练不做速度混合。换行在 tokenizer 前被压成空格，因此模型看到的是一行 Task: … Advantage: positive, State: …。策略使用相对动作，right_joint6.pos 排除在相对化之外，chunk_size 与统计重算的 CHUNK_SIZE 必须相同，当前为 32。

6. 推理

acp_inference.mode 取 no_guide 或 positive。后者构造两条字符串：基础任务，以及同一字符串加上 Advantage: positive。去噪步上

$$v=(1-\beta)\,v_{\mathrm{u}}+\beta\,v_{\mathrm{c}}.$$

$\beta\approx 0$ 只跑无条件前缀；$\beta\approx 1$ 只跑条件前缀，每步一次前向；其余 $\beta$ 才维护两套 KV。采集脚本默认 ACP_MODE=positive、CFG_BETA=1.0，因此是单路正条件。HIL 支持 RTC 后台线程与同步 predict_action，两条路径都走上述逻辑。可选 --subtask 会写进基础字符串，位于 Advantage 之前。

附录 A. 从零到一的操作

以下步骤对应仓库当前脚本。路径以脚本内变量为准，换机器时只改环境变量和 repo_id，不要在四个阶段里各写一套模式。

A.1 准备数据与环境

  1. 数据集放在 ${HF_LEROBOT_HOME}/${repo_id}。当前脚本为 /workspace/huggingface/lerobot/screw_sorting_single_sft_ep280_v30_steam。
  2. 确认 meta/episodes 含 episode_success。没有该列的回合会被当成失败。
  3. 确认相机键与脚本中的 rename 一致：cam_high、cam_right_wrist 映射到 high、right。状态与动作维度为 7。
  4. 安装本仓库，使 lerobot-value-train、lerobot-value-infer、lerobot-edit-dataset、lerobot-train 在 PATH 中。价值与策略阶段使用 4 张 GPU（脚本中 gpu_ids=0,1,2,3）。
  5. 准备 Pi0.5 基座权重，脚本指向 /workspace/lerobot/pretrained_models/pi05_base。

A.2 选定算法模式

在 scripts/run_finetune_recap.sh 中只保留一种价值模式，并让后续轮次沿用它。

RECAP_TARGET_MODE=remaining_steps   # 或 recap_returns
RECAP_N_STEP=32
RECAP_POSITIVE_RATIO=0.3
RECAP_USE_EXISTING_ADVANTAGE=false
POSITIVE_ONLY_CONDITIONAL=true
INDICATOR_DROPOUT_PROB=0.1

remaining_steps 忽略 RECAP_GAMMA 与 RECAP_FAILURE_REWARD。recap_returns 会使用它们。已有外部连续优势、且不打算重训价值时，才把 RECAP_USE_EXISTING_ADVANTAGE 设为 true，并保证 ACP_ADVANTAGE_FIELD 已在 parquet 中。

A.3 第 1 步：训练价值

RUN_VALUE_FUNCTION_TRAINING=true
RUN_VALUE_FUNCTION_INFER=false
RUN_RECOMPUTE_STATS=false
RUN_VLA_TRAIN=false
bash scripts/run_finetune_recap.sh

检查 outputs/pi06star_value_train_${repo_id}_round_${k}/checkpoints/last/pretrained_model 存在。日志中的 target_mode 必须与脚本变量一致。

A.4 第 2 步：写优势与标签

只打开 RUN_VALUE_FUNCTION_INFER。推理读取上一步的 last checkpoint，把 advantage_continuous 与 complementary_info.acp_indicator 写进数据集。日志应出现 positive_ratio_target=0.3000 以及接近它的 positive_ratio_observed。干预强制打开时，观测比例可以略高于 0.3。

抽查一帧：indicator 为 0 或 1；同一 task_index 上，indicator 为 1 的连续优势应不低于该任务阈值。

A.5 第 3 步：相对动作统计

只打开 RUN_RECOMPUTE_STATS。该步按 CHUNK_SIZE 重算统计，并排除 right_joint6.pos。必须在策略训练之前完成，且 CHUNK_SIZE 与下一步 policy.chunk_size 相同。覆盖写回同一 repo_id。

A.6 第 4 步：微调策略

只打开 RUN_VLA_TRAIN。确认命令行包含

--acp.enable=true
--acp.indicator_field=complementary_info.acp_indicator
--acp.positive_only_conditional=true
--acp.indicator_dropout_prob=0.1
--policy.use_relative_actions=true
--policy.chunk_size=32
--policy.n_action_steps=32

权重写到 outputs/pi06_policy_${repo_id}_round_${k}。若数据集没有 subtask，保持 CONDITION_ON_SUBTASK=false。

A.7 第 5 步：采集下一轮数据

把 scripts/run_hil_collect_data.sh 的 --policy.path 指到刚保存的 pretrained_model。默认

ACP_MODE=positive
CFG_BETA=1.0
SUBTASK=

启动后日志应包含 ACP infer: mode=positive 以及带 Advantage: positive 的条件提示。需要无条件对照时设 ACP_MODE=no_guide。需要更强或更弱引导时改 CFG_BETA（偏离 1 会变成双路去噪，更慢）。

采集时：空格暂停，c 接管，p 交还策略，方向键结束回合。打开结局标注时，未按成功/失败键的回合使用脚本中的默认标签。记录列是高层 task、is_intervention 和 episode_success，不是 Advantage 字符串。

A.8 第 6 步：进入下一轮

  1. 把新采集数据与原数据合成一个 LeRobot 数据集，或把 repo_id 改为合并后的目录。
  2. k 加 1，避免覆盖上一轮 outputs/。
  3. 从 A.3 重做。不要更换 RECAP_TARGET_MODE，除非同时丢弃旧的价值 checkpoint 与 indicator。
