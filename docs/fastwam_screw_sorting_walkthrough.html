FastWAM 在螺丝分拣数据上的完整计算过程

数据集 /data/huggingface/lerobot/lerobot/screw_sorting_single_sft_ep280_v30_steam。下面按 LeRobot 默认 FastWAM 配置，把这条数据从采样、前处理、训练损失到推理去噪走一遍。形状和一次数值例子都按这份数据的 meta/info.json 与 meta/stats.json 计算。

目录名写的是 ep280，元数据里实际是 279 条轨迹、115130 帧、30 fps、1 个任务。任务原文：Please sort and return the silver screws in the grey box to their proper places.

0. 这份数据长什么样

字段形状 / 类型含义
observation.images.high视频 480×640×3头顶相机，HWC
observation.images.right视频 480×640×3右腕相机，HWC
observation.statefloat32 [7]右臂 7 个关节，含夹爪 right_joint6.pos
actionfloat32 [7]同名的 7 维目标关节

关节统计（用于后面的 mean/std 归一化）：

state mean = [0.1951, 1.3723, -1.0164, 0.0354, 0.7873, 0.0116, 0.0048]
state std  = [0.2194, 0.7205,  0.3850, 0.0820, 0.2080, 0.0993, 0.0091]
action mean = [-0.0001, 0.0096, -0.0054, -0.0001, 0.0024, 0.0002, 0.0053]
action std  = [ 0.0981, 0.3288,  0.1846,  0.0366, 0.1070, 0.0342, 0.0093]

默认 FastWAMConfig.proprio_dim = 8 对不上这 7 维状态。下面的推导把 proprio_dim 和 action_dim 都设为 7。图像仍用默认 image_size = (224, 448)：两路相机各缩到 224×224，沿宽度拼成 448。

1. 一次训练样本取哪些时刻

默认 num_video_frames = 33，action_video_freq_ratio = 4，action_horizon = 32。当前帧记为数据集下标 t。

视频只取每隔 4 帧的观测，来自 observation_delta_indices：

deltas = [0, 4, 8, 12, 16, 20, 24, 28, 32]
帧号   = t + deltas
模型帧数 model_video_frames = (33 - 1) / 4 + 1 = 9
约束：9 % 4 == 1，VAE 时间下采样才合法

动作取连续 32 步，来自 action_delta_indices = range(32)，即 action[t : t+32]。32 能被视频间隔数 8 整除，所以每两个相邻视频帧之间正好对应 4 个动作。

t 的两路图像 + state 未来 8 个视频帧 未来 32 个动作 任务字符串

30 fps 下，这 32 个动作覆盖 32/30 ≈ 1.067 s。视频帧的时间戳是 0、4/30、8/30 … 32/30 秒。

2. 前处理：LeRobot processor

make_fastwam_pre_post_processors 的输入流水线只有四步，没有图像归一化，也没有在这里改分辨率：

rename_observations → add_batch_dim → to_device → normalize

归一化表是 VISUAL=IDENTITY，STATE/ACTION=MEAN_STD。图像保持数据集解码后的 [0, 1]。状态和动作做：

x_norm = (x - mean) / std

数值例子。设某一帧 state[0] = 0.1951（正好是均值），action[0] = 0.1000：

state_norm[0]  = (0.1951 - 0.1951) / 0.2194 = 0
action_norm[0] = (0.1000 - (-0.0001)) / 0.0981 = 1.0194

7 维都这样算，得到 state_norm、action_norm，形状仍是 [7]，进 batch 后是 [B, 7] 和 [B, 32, 7]。

图像真正的缩放发生在模型里的 _stack_video_from_images，不在 processor。两路 key 按名字排序是 high 然后 right。每路从 [B, 9, 3, 480, 640] 双线性缩到 [B, 9, 3, 224, 224]，再沿最后一维拼接：

[B, 9, 3, 224, 224] ∥ [B, 9, 3, 224, 224]
        → [B, 9, 3, 224, 448]
permute → video [B, 3, 9, 224, 448]

语言不进这个 processor。模型在 _batch_to_training_sample 里用冻结的 UMT5 把任务句子编成 context [B, L, 4096] 和 context_mask [B, L]，L ≤ 128。

3. 训练：从像素到两个速度场

调用链：

FastWAMPolicy.forward
  → _batch_to_training_sample
  → FastWAM.build_inputs
  → _sample_training_targets
  → _run_training_mot
  → loss = 1.0 * loss_video + 1.0 * loss_action

3.1 VAE 编码

Wan2.2 VAE 空间下采样 16、时间下采样 4、latent 通道 48。9 帧视频变成：

T_lat = (9 - 1) / 4 + 1 = 3
H_lat = 224 / 16 = 14
W_lat = 448 / 16 = 28
input_latents: [B, 48, 3, 14, 28]

第 0 个 latent 帧被单独保存为 first_frame_latents [B, 48, 1, 14, 28]。本体只取第 0 帧：proprio[:, 0, :] 得到 [B, 7]，编码后接到 text context 后面。

3.2 加噪：两条独立的直线流

调度器 train_shift = 5，num_train_timesteps = 1000。对一个均匀随机数 u ∈ (0, 1)：

σ = 5u / (1 + 4u)
timestep = σ * 1000
x_t = (1 - σ) * x + σ * ε
目标速度 v = ε - x

视频和动作各抽各的 u。例子：视频抽到 u = 0.5：

σ_video = 2.5 / 3 = 0.8333
timestep_video = 833.3
latents = 0.1667 * input_latents + 0.8333 * ε_video
target_video = ε_video - input_latents

动作若抽到 u = 0.2：

σ_action = 1.0 / 1.8 = 0.5556
timestep_action = 555.6
noisy_action = 0.4444 * action_norm + 0.5556 * ε_action     # [B, 32, 7]
target_action = ε_action - action_norm

加噪之后，第 0 个视频 latent 被写回干净的 first_frame_latents。未来两帧保持噪声，当前帧是条件。

3.3 切 token，送进 MoT

视频 patch 是 [1, 2, 2]。每一帧 latent 14×28 变成 (14/2) × (28/2) = 98 个 token。3 个 latent 帧共 294 个视频 token，隐藏维 3072（24 头 × 128）。动作序列长度就是 32，每个动作一步一个 token，动作 expert 隐藏维 1024，注意力投影仍是 24×128。

当前帧的 98 个 token 排在视频序列最前面，它们的时间嵌入被写成 0。注意力掩码：

谁看谁是否允许
当前帧 token → 未来视频 token否（first_frame_causal 把左上块对未来清掉）
未来视频 token → 当前帧 token是
视频 token → 动作 token否
动作 token → 当前帧的 98 个 token是
动作 token → 未来视频 token否
动作 token → 全部动作 token是

所以动作损失读不到未来画面。未来画面只通过视频自己的速度损失来学习。共享的是同一套 MoT 层的权重，不是让动作直接看见未来帧。

3.4 损失

两个头各自输出速度，和 ε - x 做 MSE。视频损失丢掉第 0 个 latent 步（它是条件，不是预测目标），只在后 2 个 latent 帧上平均；image_is_pad / action_is_pad 为真的步不计入。再乘时间权重：

y = exp(-2 * ((t - 500) / 1000)^2)
weight = (y - y_min) / mean(y - y_min)

loss = 1.0 * mean(video_mse * weight_video) + 1.0 * mean(action_mse * weight_action)

可训练的是 MoT 和 proprio 编码器。VAE 与 UMT5 冻结，不写进策略的 model.safetensors。

4. 后处理

训练没有把动作解码回关节角。推理时 predict_action_chunk 得到的是归一化空间的 [B, 32, 7]，再走 postprocessor：

unnormalize →（可选）gripper toggle → to_cpu

反归一化是前处理的逆：

action_raw = action_norm * std + mean
例：action_norm[0] = 1.0194
    action_raw[0] = 1.0194 * 0.0981 + (-0.0001) = 0.1000

这份机器人数据不要开 LIBERO 的 toggle_action_dimensions。那个开关默认是空列表；若设成 [-1]，会把夹爪维从 [0,1] 映到符号 ±1，和这里的连续关节角不一致。

select_action 并不把 32 步一次发出去。它只把前 n_action_steps 步放进队列（默认 32，即整块），每次控制循环弹出 1 步。队列空了再预测下一块。

5. 推理：当前帧如何进 MoT

rollout 调用的是 select_action → predict_action_chunk → infer_action，不是会生成未来视频的 infer_joint。

实时观测通常只有当前这一帧。两路图仍缩成 [1, 3, 224, 448]，VAE 只编这一帧：

first_frame_latents: [1, 48, 1, 14, 28]
patch 之后: 98 个 token，每个 3072 维
时间嵌入: 全部写成 0，表示 σ = 0，输入已经是干净画面

这 98 个 token 过 30 层视频 Transformer，每层只留下 K/V，不走视频速度头 post_dit：

列表长度 30
每一层 k, v: [1, 98, 3072]
3072 = 24 个头 × 128，头被拼在最后一维
注意力时才拆成 [1, 24, 98, 128]

动作从 [1, 32, 7] 的高斯噪声开始。默认推理步数下，action scheduler 给出一串 σ 和步长 delta = σ_next - σ。每一步：

动作 token 的 Q,K,V 按当前噪声重新算
K_cat = concat(当前帧的 K, 动作的 K)    # 序列维 98 + 32
V_cat 同样拼接
动作 query 同时看这 98 个画面 token 和 32 个动作 token
速度头输出 v_action，形状与噪声相同
x ← x + v_action * delta

当前帧的 K/V 在这 32 步动作去噪里不更新。循环结束时 x 就是归一化动作 [32, 7]，再按第 4 节乘回 std、加回 mean，得到要发给右臂的 7 个关节目标。

6. 和这份数据对齐时要改的配置

proprio_dim8必须改成 7
image_size(224, 448)两相机可保持：各 224×224，宽向拼接
input_features单相机声明 high 与 right，形状 (3, 224, 224)
toggle_action_dimensions[]保持空
视频 / 动作窗口33 帧抽 9，动作 32可直接用；要改窗口必须同时满足第 1 节的整除约束
