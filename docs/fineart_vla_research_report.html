1. 摘要与问题设定

FineART-VLA（Scale AI × Hugging Face）是一条端到端 Vision-Language-Action（VLA）策略： 在 π0.5 的「视觉—语言前缀 + 连续动作 Expert」之上，重新打开并训练 PaliGemma 的语言模型头， 使同一份 checkpoint 既能生成低层子任务（System 2），又能在该语言条件下用流匹配预测动作（System 1）。

中期预训练使用 FineART 数据集：约 40,543 条双臂操作轨迹（约 1,718 小时）， 含 533,913 条子任务标注。下游在自有 LeRobot 数据集上微调时，必须提供与所选 Recipe 匹配的语言列； 策略本身不会从「只有 task 字符串」的普通数据集里自动发明子任务监督。

默认因式分解：  π(a | o, subtask) · π(subtask | o, task)

即：高层用任务与观察预测 subtask；低层用当前 subtask、观察与本体状态预测动作块。 运行时由 rollout 按节奏交替调用这两条路径，而不是在一次前向里同时吐出文字和动作。

3.2 时间语义

Persistent 行在采样时刻 t 上取「最新且 timestamp ≤ t」的那条（resolver：active_at(t, style=…)）。 Event 行必须精确落在帧时间戳上，没有容差窗口。因此标注流水线应用数据集帧时间做 snap，而不是随意浮点。

3.3 Recipe 渲染（Layer 2 → Layer 3）

数据集本身不绑定某一种训练对话格式。训练时由 Recipe YAML（或内嵌 dict）声明 bindings 与 messages， RenderTrainingMessagesStep 把每帧语言解析成 HF 风格 messages，并附带：

  • message_streams：high_level / low_level，决定是否走动作流损失；
  • target_message_indices：哪些 assistant 回合算文本 CE 目标。

默认内嵌配方（30% / 70%）

定义于 FineARTVLAConfig 的 _fineart_vla_default_recipe()：

分支权重输入监督
high_level_subtask 0.30 User: ${task} Assistant: ${subtask}（文本 CE，不预测动作）
low_level_execution 0.70 User: ${subtask} + 离散化 State 动作 flow（及可选 FAST）；无文本目标

扩展配方

  • configs/recipes/subtask.yaml：与默认相同的核心。
  • configs/recipes/subtask_mem.yaml：加入 memory 更新（约 15%）。
  • configs/recipes/subtask_mem_vqa_speech.yaml：再加入插话应答与按相机拆分的 VQA。
  • configs/recipes/subtask_joint.yaml：同一前缀上联合监督 subtask 文本与动作（需匹配的 runtime 因果标记）。
默认配方不读取 memory。数据集里即便有 memory，也只有换成 subtask_mem.yaml 才会进入损失。 默认 runtime 控制器也只接受一句 subtask，不会把 memory 直接塞进动作头。

4. 模型架构（图解 + 张量形状）

4.1 端到端总览

FineART-VLA 在 π0.5 的「视觉—语言前缀 + 动作 Expert 后缀」上，额外打开 PaliGemma lm_head，形成三条可训练路径。数学上把策略写成因式分解：

默认概率因式分解 πθ(a, s | o, g)  =  πθlang(s | o, g)  ·  πθact(a | o, s)

其中 g 是高层目标（task / Autosteer goal），s 是低层 subtask 字符串， a ∈ ℝH×d 是动作块（H=chunk_size=50，d 为机器人动作维，内部 pad 到 max_action_dim=32）。 训练时两条路径按 recipe blend 分样本学；推理时由 rollout 交替调用。

图 2 · FineART-VLA 架构总览：前缀（绿）与后缀（金）进入联合 Transformer，再分出三头。

4.4 Knowledge Insulation

目标：连续动作损失不破坏预训练 VLM。设前缀参数为 φ，Expert / 动作投影为 ψ。

KI 打开时的梯度约束 ∂Lflow / ∂φ  =  0，   ∂Ltext / ∂φ  允许非零

实现两道闸：

  1. flow-only（无 text/FAST 标签）时 embed_prefix 包在 torch.no_grad()；
  2. 联合层传入 suppress_prefix_grads=True，在注意力里切断动作→前缀 K/V 的反传。
# FineARTVLAPytorch.forward / Policy._compute_all_losses_fused
suppress_prefix = knowledge_insulation and text_labels is None and action_tokens is None
with torch.no_grad() if suppress_prefix else nullcontext():
    prefix_embs, ... = embed_prefix(...)
ki_kwargs = {"suppress_prefix_grads": True} if suppress_prefix else {}
(prefix_out, suffix_out), _ = paligemma_with_expert.forward(..., **ki_kwargs)

5.1 总目标

加权多任务损失 ℒ(θ) = λflow ℒflow + λtext ℒtext + λfast ℒFAST

默认 λflow=10，λtext=1，λfast=1。 Recipe blend 决定每个样本启用哪些项：high_level 样本通常只有 ℒtext； low_level 样本有 ℒflow（+ 可选 ℒFAST），文本标签为空。

图 4 · 一个 batch 内不同样本启用不同损失项；路由掩码是 predict_actions / text_labels。

5.2 流匹配动作损失（NOISE_AT_ONE）

FineART / π0.5 使用 FlowConvention.NOISE_AT_ONE： t=1 是纯噪声，t=0 是干净动作。直线插值路径与目标速度场为：

xt = t · ε + (1 − t) · a，   ε ∼ 𝒩(0, I)
ut ≜ dxt/dt = ε − a   （与 t 无关的常速度）
vθ(xt, t | o, lang) ≈ ut
ℒflow = 𝔼a,ε,t,o [ ‖ vθ(xt, t | o, lang) − (ε − a) ‖22 ]  （对真实动作维求均值）

modeling_fineart_vla.py · FineARTVLAPytorch.forward / _combined_prefix_and_flow

time_expanded = time[:, None, None]          # (B,1,1)
x_t = time_expanded * noise + (1 - time_expanded) * actions
u_t = noise - actions
...
v_t = self.action_out_proj(suffix_out[:, -chunk_size:])
flow_per_dim = F.mse_loss(u_t, v_t, reduction="none")
flow_per_dim = flow_per_dim[:, :, :original_action_dim]  # 去掉 pad
per_sample = flow_per_dim.mean(dim=(1, 2))
ℒ_flow = _reduce_action_loss(per_sample, predict_actions_t)

K-repeat 摊销

flow_num_repeats=K（默认 5）：对同一前缀独立抽 K 组 (ε, t)， 把 K 个 suffix 拼成长度 K·H，注意力块对角，使各组互不可见。损失对 K 维再平均：

ℒflow(amort) = (1/K) Σk=1K ‖ vθ(xt(k), t(k)) − u(k) ‖2

前缀只编一次，相当于用 K 倍动作监督摊薄昂贵的视觉—语言编码。

5.4 FAST 离散动作 CE

z = FASTEncode(a) ∈ {1…VF}F
把 z 嵌进前缀末端，用同一 lm_head：
ℒFAST = − Σj∈code log pθ(zj | prefix, z<j)

段感知掩码保证：语言位置看不到 FAST，动作后缀也看不到 FAST， 因此可与 ℒtext / ℒflow 共享一次前向而不「偷看答案」。 id 偏移由 fast_skip_tokens=1152 控制，避开 <loc> 段。

6.1 双环、双速率

推理把训练时的因式分解拆成两次独立调用（由 rollout 编排，模型不会在 select_action 里偷偷再生成文字）：

推理调用 s ← GenerateText(o, g)  ;   a ← EulerIntegrate(vθ(· | o, s), ε, N)
环路触发API输出典型耗时
语言 Autosteer 到期 / /vqa generate_text subtask 字符串 数百 ms–数 s
动作 控制 tick / RTC 填队列 select_action → sample_actions a ∈ ℝH×d N 次 denoise（默认 N=10）
图 5 · 语言慢、动作快：间隔只在 subtask 应用之后重新计时，慢生成不会饿死控制。

6.2 语言生成（自回归 + KV cache）

Autosteer 把 goal 放进 QUERY_TEXT，RenderRuntimeMessagesStep 用 checkpoint 的 recipe 取出监督 ${subtask} 之前的 turns 作为 prompt（通常就是 User: {goal}）， 再 tokenize。生成过程：

1) 编码多模态前缀 Eprefix，建立 KV cache
2) 对步 n=1…Nmax：
   logits = lm_head(hlast)
   屏蔽 FAST 词表段；可选屏蔽 <loc>（subtask 时 suppress_loc_tokens=True）
   wn = argmax(logits)  或  nucleus(softmax(logits/T))
   若 wn=EOS 则停；否则只把新 token 嵌入送进 cache
3) decode(w1:n) → subtask 字符串

modeling_fineart_vla.py · select_message

for _ in range(max_new_tokens):
    if cache is None:
        step_embs = current_embs                  # 整段前缀
    else:
        step_embs = new_emb                       # 仅新 token
    (vlm_out, _), cache = backbone.forward(
        inputs_embeds=[step_embs, None], past_key_values=cache, use_cache=True)
    last = _last_valid_prefix_hidden(vlm_out, current_pad)  # 避开右 padding
    logits = lm_head(last)[:, -1]
    logits[..., fast_lo:256000] = -inf            # 抑制 FAST 泄漏
    if suppress_loc_tokens:
        logits[..., 256000:257024] = -inf
    tok = argmax_or_sample(logits)
    if tok == eos: break
    new_emb = backbone.embed_language_tokens(tok)

6.3 动作采样：ODE 的 Euler 积分

训练学到速度场 vθ ≈ ε − a。推理从纯噪声 x1=ε 出发，沿同一约定积分到 t=0：

x1 = ε ∼ 𝒩(0, I)
Δt = −1/N   （N=num_inference_steps，默认 10）
对 k = 0…N−1：  tk = 1 + k·Δt
   vk = vθ(xtk, tk | o, s)
   x ← x + Δt · vk
得到 x0 ≈ â
图 6 · NOISE_AT_ONE 下的 Euler 去噪轨迹。实现：euler_integrate + FineART 的 denoise_step。

    inputs_embeds=[prefix_embs, None], use_cache=True)
# 2) Euler
return euler_integrate(
    lambda x_t, t: self.denoise_step(prefix_pad_masks, past_key_values, x_t, t),

12. 实现机理与编码技巧

这一章对着 modeling_fineart_vla.py 和 pi05/modeling_pi05.py 的 compute_layer_complete，把「数值上等价、梯度上不等价」的技巧拆开。 读代码时按这个顺序：损失路由 → 知识隔离 → 因果标记 → FAST 防泄漏 → CE 分发 → 推理缓存。

12.1 两级知识隔离：前向不变，梯度被切开

Knowledge Insulation 的论文要求是：动作损失不能通过注意力改写预训练 VLM，但前向输出必须和「不隔离」时一样。 实现拆成两级，不要混成一件事。

动作 query 看到的 K/V Kaction = [detach(KVLM) ; Kexpert]， Vaction 同样。
VLM query 仍使用未 detach 的 K/V。

pi05/modeling_pi05.py · compute_layer_complete，约 275–290 行

prefix_len = inputs_embeds[0].shape[1]
key_for_action = cat([key_states[:, :, :prefix_len].detach(), key_states[:, :, prefix_len:]], dim=2)
value_for_action = cat([value_states[:, :, :prefix_len].detach(), value_states[:, :, prefix_len:]], dim=2)
att_vlm = attend(q_vlm, key_states, value_states, ...)          # 文本损失仍能更新 VLM
att_action = attend(q_action, key_for_action, value_for_action, ...)  # flow 梯度停在 detach

detach 不改变数值，只切断动作 query 对 VLM K/V 的反传。VLM 自己的 query 仍走未 detach 的 K/V， 所以 L_text 和 L_FAST 可以训练 PaliGemma。这也是配置里禁止 train_expert_only=true 同时又开文本/FAST 的原因：那会冻住文本损失要更新的塔。

第二级只在「这一步根本没有文本/FAST 标签」时打开：suppress_prefix_grads=True。 此时前缀 embedding 和 VLM 流包进 torch.no_grad()，省掉一条数学上已经是死图的反向。 有文本标签时这一级必须关掉，否则 L_text 也没梯度。

开关在 FineARTVLAPolicy.__init__： self.model.paligemma_with_expert.knowledge_insulation = config.knowledge_insulation。 库存 Pi05 这条标志是关的。Flex / manual attention / FlashRT AdaRMS 都要求 KI 打开，否则配置直接报错。

12.2 目标 span 改成因果，提示仍双向

π0.5 的图像+语言前缀默认是双向注意力（embed_prefix 里 att 标记全 0）。 自回归文本损失不能让第 i 个目标 token 看见 i+1。技巧是不重写整段 mask，只把「labels ≠ -100」的位置 OR 进因果标记： 

# _mark_target_span_causal
target = text_labels[:, :n] != -100
att[:, lang_start:lang_start+n] = att[:, lang_start:lang_start+n] | target

make_att_2d_masks 把这些 1 解释成「新的注意力段起点」，于是 prompt 仍双向，被监督的 assistant 片段变成因果。 推理若走 joint-sequence（生成的 subtask 留在前缀里再出动作），必须用同一套标记： sample_actions(..., lang_causal_marks=...) 在 embed_prefix 末尾调用 _apply_causal_language_marks。否则训练时因果、推理时双向，分布对不上。

12.3 FAST 三处防泄漏

  1. 动作 query 看不见 FAST token。 att_2d_masks[:, fast_end:, fast_start:fast_end] = False。 否则 flow 头可以直接读出离散动作码，连续损失变成抄答案。
  2. RoPE 位置从非 FAST 前缀重新起算。 训练时 FAST 占了一段序列位置；推理出动作时没有 FAST。 若 suffix 的 position id 接着 FAST 往下数，和推理不一致。代码把每个 flow 块的位置设成 non_fast_valid + cumsum(suffix_pad) - 1。
  3. 生成文本时屏蔽 FAST 和可选的 loc 段。 select_message 把 [fast_lo, 256000) 的 logits 打成 −∞； subtask/memory/plan 还可屏蔽 [256000, 257024) 的 <loc>。 VQA 不能屏蔽 loc，答案本身就要这些 token。 fast_skip_tokens=1152 就是为了让 FAST 码和 loc 不占同一行嵌入。

12.4 文本 CE：移位、分桶、z-loss

shift：hidden[:, :-1] 预测 labels[:, 1:]（标准 next-token）
有效位以外 labels = −100，cross_entropy 的 ignore_index
z-loss：α · mean( logsumexp(logits)² )，α = 1e-4，只加在有效位上

分发器 _lin_ce_flat 按行数选实现，避免一种 kernel 打所有形状：

  • 有效行数 ≤ 2048：物化 hidden @ Wᵀ，在 FP32 logits 上算 CE。可选 torch.compile，但 compile 函数懒加载，import 模块时不碰 Dynamo。
  • 更长且稀疏：先扔掉 −100 行，再补到 2 的幂（1 << bit_length），让 compile 的形状稳定，padding 行仍标 −100。
  • 再长：走 Liger 的 fused linear CE，不物化整张词表 logits。lse_square_scale 就是 z-loss。

FAST 的 CE 多一步：按每个样本的有效 token 数分组，同长度的样本拼成一块再算。 掩码写进 labels（where(valid, id, -100)），避免为了 mask 做一次 GPU→CPU 同步，也方便图捕获。

12.5 K 次 flow 共用一个前缀

flow_num_repeats=5 时，前缀编码一次，K 组独立 (ε, t) 的 suffix 在序列维拼成 K·H。 注意力是块对角：第 k 组动作只看前缀（且不看 FAST）和自己这 H 步，组与组互不可见。 损失对 K 平均。数值上等价于 K 次独立 flow，算力上前缀只付一次。

FlexAttention 只在 KI 且 K>1 时允许打开。mask 用两个 block mask：VLM 行、动作行。 消费级 GPU 共享内存 < 128KB 时把 tile 缩到 BLOCK_M1=32 等，否则 head_dim=256 的反向会爆。 Flex 和 manual attention 互斥。manual 路径把 softmax 放在 FP32，专门对付低 flow timestep、大 QK 时 BF16 softmax 的梯度问题。 类属性 fp32_joint_attention = True 是同一动机在默认 SDPA 路径上的开关。

12.6 推理：crop 而不是 clone

Pi05 的 denoise_step 每步 clone_past_key_values，因为 suffix 会把 K/V 追加进 cache。 FineART 在 Expert 前向之后调用 past_key_values.crop(prefix_len)，把刚追加的 suffix 裁掉，前缀 cache 原地复用。 语言生成则相反：第一步跑完整前缀并 use_cache=True，之后每步只送一个新 token。 右 padding 的 prompt 不能从最后一列取 logits，所以用 _last_valid_prefix_hidden 按 attention mask 取最后一个有效位置。 

# denoise_step 末尾
past_key_values.crop(prefix_len)
return self.action_out_proj(suffix_out[:, -chunk_size:])

# select_message：cache 命中后
step_embs = new_emb
att_2d = current_pad[:, None, :]          # 新 token 能看见全部已有 key
last = _last_valid_prefix_hidden(vlm_out, current_pad)

12.7 优化器分组与缺头初始化

get_optim_params 把参数拆成最多四组，余弦调度对每组乘同一个 lambda，比例在衰减中保持不变：

组匹配学习率
backbonePaliGemma 除 lm_head / embed_tokensbase × backbone_lr_scale
action_expertGemma expert、action 投影base × action_expert_lr_scale
conditioningtime MLP、AdaRMS 的 dense（仅 scale≠1 时拆出）expert × conditioning_lr_scale
lm_headlm_head 与 embed_tokens 绑在同一组base × lm_head_lr_scale

从 pi05_base 加载时，π0.5 权重里常常没有训练过的 lm_head。 _prepare_pretrained_state_dict 在缺键时把 embed_tokens.weight clone 过去， 避免语言头随机初始化把已经对齐的嵌入空间打散。tied embedding 和 head 放进同一优化器组，是为了之后若解绑也不会用两个学习率拧着更新。

12.8 融合核刻意没开的部分

use_liger_kernels 只融合 PaliGemma 的 RoPE 和 GeGLU。 LayerNorm / RMSNorm 在 SigLIP 的形状上变慢，交叉熵也关掉，因为文本损失走自己的 _lin_ce_flat。 Liger 会改进程内的 transformers，同进程里别的 PaliGemma 策略也会被换 kernel。 FlashRT AdaRMS 只包 Expert 的条件归一化，失败则退回 eager，不让可选依赖挡住训练。

12.9 读代码时的检查单

  1. FineARTVLAPolicy.forward：这一 step 的 run_flow / run_text / run_fast 哪个为真。
  2. suppress_prefix_grads 是否因为存在文本标签而是 False。
  3. 注意力里 suffix→FAST 是否被置 False，suffix 的 RoPE 是否从非 FAST 前缀重起。
  4. 文本 labels 是否只覆盖 assistant 目标，并且该 span 被标成因果。
  5. 推理 generate_text 是否屏蔽了 FAST 段；VQA 是否保留了 loc。
  6. denoise_step 是否 crop 而不是把前缀 cache 拷走。
  7. checkpoint 里的 recipe 是否已经内嵌（recipe_path 在保存前被清空），推理 prompt 才和训练一致。

10. 故障排查与工程建议

现象优先检查
没有 text_loss / 不会生成 subtask 语言列是否存在；recipe 能否 bind；text_loss_weight>0；checkpoint 是否带 recipe
subtask 像样但动作失败 子任务时间边界；state/action 归一化；低层样本是否真的在训（70% 分支）
